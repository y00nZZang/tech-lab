# Istio sidecar 경로의 unary RPC 1회 관찰

## 출처와 실행 조건

2026-10-07 실습 대화에서 사용자가 제공한 kubectl 실행 출력을 2026-10-08 문서화했다. 독립적인 원본 JSON 파일은 보존되어 있지 않다. 재실행 결과가 아니다.

- Istio 1.31.1 minimal, 단일 노드 kind, 별도 grpc-lb-mesh-lab namespace
- Backend 2개와 client에 sidecar 주입, 각 Pod 2/2 Ready 확인
- 대상: backend-mesh.grpc-lb-mesh-lab.svc.cluster.local:50051
- 앱 정책: pick_first, 200 unary RPC, 동시성 20
- 실행 전 예상: 200/0, 확신도 10%

## 관찰

| 항목 | 출력 값 |
|---|---|
| Pod별 RPC | 100 / 100 |
| duration_ms | 1485.33 |
| throughput_rps | 134.65 |
| latency p50 / p95 / max (ms) | 147.75 / 213.1 / 265.31 |
| server queue p50 / p95 / max (ms) | 49.96 / 99.46 / 104.99 |

## 해석과 한계

앱의 주소 선택과 outbound Envoy의 Backend 선택은 다른 단계다. 이번 sidecar 경로에서는 HTTP/2 요청을 프록시가 처리했다.[^architecture] 분포만으로 실제 연결 수나 모든 라우팅 설정을 입증하지 않는다. 단 1회 관찰이며, 항상 100/100 또는 성능 우위라는 결론을 내리지 않는다. 운영 환경 도입 사례가 아니다.

실행 절차는 [실험 README](../README.md)의 Istio 절과 [매니페스트](../k8s/istio-lab.yaml)에 있다.
